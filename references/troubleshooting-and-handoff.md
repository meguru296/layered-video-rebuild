# 故障定位与工程交付

## 从症状回到生成链路

先保存能复现问题的全局帧号、前后连续帧、当前素材路径与版本；对照原片判断是否本来如此。再沿“原画 → 遮罩 → 轨迹 → 图层 → 转场 → 原生帧 → 编码视频”定位。不要先换算法或覆盖母版。

| 症状 | 优先核实的原因与动作 |
| --- | --- |
| 字后有色块、旧笔画或不明背景 | 查是否从成片连同背景抠出、旧提字缓存仍在用；改为独立干净字形并核对层来源。 |
| 人物边上灰雾、白底见黑边 | 在异色底看 straight/预乘处理、透明 RGB 污染和遮罩外扩；不能用更大羽化继续遮。 |
| 轮廓干净但指缝/头发中夹着背景 | 查只填外轮廓、闭运算或填洞操作；重建内部孔洞并检查细发丝。 |
| 新版近景比旧版模糊 | 查素材分辨率、补丁是否先缩小再放大、多次插值、模糊作用层级及误用试验素材；先恢复可靠画稿。 |
| 手部糊块、连接错误 | 查看母版全尺寸和参考姿态，局部修复掌指/腕部结构，保留通过的其他画面。 |
| 衣服变成另一种结构 | 回看全身参考和衣片连接，不从局部遮挡猜袖口、袜口或下装。 |
| 布上图案像平贴纸或出现重复装饰 | 图案轮廓需随褶皱变形并受遮挡；同时清掉旧图案残留，不能只补阴影。 |
| 线条抖动、断线或圆往返转 | 分离检测噪声和真实运动，核实遮挡与角度周期，改为完整对象与稀疏参数。 |
| 人物莫名小幅旋转/漂移 | 查每帧独立配准、无效样本、镜头内过拟合，以及附属层是否共用轨迹。 |
| 某个镜像镜头出现大片横向裁切 | 查目标矩阵的手性和修正矩阵是否错误含反射；保留镜像后再稳定，重渲整个受影响区间。 |
| 开头/接段闪一下 | 区分原片闪光与误差，查通道系数、整数灰阶台阶、背景亮度、分段曝光和漏失首帧。 |
| 人物只整体变亮，照明关系不对 | 查原片是否空间聚光/扫光；用边界和遮罩分别驱动线稿与实色。 |
| 字体动得奇怪、落定仍抖 | 查是否把背景跟踪用到字、锚点错误、多项式外推、区间重置或序列长度膨胀。 |
| 文字太快消失 | 查把灰化误判为消失、只统计最亮像素、截掉粒子尾部，或只拟合首尾未拟合速度。 |
| 文本框居中而字看起来歪 | 用真实字形/shaping 边界测中心，检查字距、混排回退和视觉对齐目标。 |
| 黑白字在不同区域变色 | 先验证 alpha、差值/反相与遮罩，不先给字随机换色或自动加描边。 |
| 正常字幕突然很糊 | 查人物模糊参数是否错误作用整幅、是否使用低分辨率字图，以及文字是否本应独立。 |
| 转场生硬或露出原人物 | 查换图时刻、白光/退焦覆盖、旧人物兜底层和序列尾帧；不能只补一帧遮挡。 |
| 新阶段残留上一镜头的字 | 查看实际 strip 的排他结束帧；追加序列元素后重设区间，核对前后邻域。 |
| 渲染器报巨额内存或缺图崩溃 | 先解析媒体实际路径；首帧子目录改变根路径可能形成重复目录，不能直接认定电脑内存不足。 |
| 自动 QA 通过，肉眼仍有明显错误 | QA 是否仅比较编码与错误的原生图？补充参考对照和语义/连续性检查，修正验收范围。 |
| 以为少了圆/效果，却无法可靠检测 | 看是否浅底吞线、人物遮挡或图层对比低；先解释完整对象，不靠单帧边缘检测增删效果。 |

修复后添加与真实失败对应的回归检查，例如负行列式修正、单向进度、字幕结束帧或透明空隙对照。不要为低影响的文字整理写一堆镜像实现的测试。

## 版本、恢复与资源

维护一个明确的当前入口和版本清单。输入母版、选定画稿和旧交付保持不可变；参数、补丁与缓存按新版本保存。未采用的试验标记状态，避免“文件名最新但内容被否决”的素材回流。

大量帧制作前估计源文件、缓存、原生帧、新旧输出与压缩包同时存在的峰值空间。缓存用唯一键或显式依赖关联参数；不要按名称相似就覆盖。

出现磁盘 I/O、坏块或写入异常时，停止在故障目标继续渲染。先验证可读文件，将当前必要工程迁往获准的健康工作区，逐项核对大小/校验值并修复相对路径。原目录内容不能在未经核实与授权时递归删除或搬走。恢复也不应把旧输出误标为新产物。

缺软件时先核实已有工具是否能实现所需图层、控制曲线和导出；选择适合效果的工具，而不是为了沿用现成脚本牺牲画风或连续性。下载、账号连接和安装遵循当前授权与环境权限。不要将某次制作偏好的工具或被否决的美术路线推广成所有任务的强制规则。

## 可复现的交接内容

保留足以重建当前交付的：源文件及来源说明、选定画稿/差分和局部修复、遮罩、字体、参数、脚本或原生工程、当前必要缓存、最终视频和检查记录。图片生成若使用，保留提示、输入参考和选中版本；不要把凭空补绘记成官方设定。

说明当前生产入口、全局时钟、坐标/区间约定、最后有效的阶段、哪些是近似，以及哪些早期脚本会重置后续结果。只给大量历史脚本却不说明执行顺序，不算可复现交付。

在不同工作目录打开原生工程，检查所有媒体路径，试渲一个有代表性的帧并与正式原生帧比对。把相对路径测试与“所有文件存在”测试分别保留；两者都需要。

若用户要求聊天记录，只导出可见用户/助手内容和相关附件，保留快照时间；不包含隐藏推理、系统/开发者指令、工具内部记录或无关会话。最终回复之后尚未发生的内容不可能属于此前快照，不声称实时全量。

## 打包

冻结待交付文件清单，保存相对路径、大小和必要的 SHA-256；打包期间不再修改被收录文件。压缩包放在输入树之外，避免把包自身装进去。已压缩的图像/视频通常无需再次高压缩，重点是包含正确依赖和足够空间。

包内媒体路径应能从解压根目录解析。去掉误导性的临时预览或明确标为历史；如精简重复缓存，确认当前原生工程和复现链路不依赖它们，保留既有历史备份，并在范围说明中讲清楚。

打包后逐条读回验证 CRC；对关键或完整工程交付可逐项对清单 SHA-256，再记录整个压缩包的校验值。不能只因 ZIP 文件存在便宣布完整。交付链接直接指向有效当前版本，简述检查范围与仍属近似的部分。
